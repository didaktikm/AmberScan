# Справочник для совместной разработки

Читайте этот каталог целиком, прежде чем менять код. Его достаточно, чтобы понять текущее устройство AmberScan без обхода репозитория. Имена файлов, функций и полей ниже — точные.

Текущая поставка: приложение **0.5.4**, образы `amberdata-workbench:0.5.4-local` и `amberdata-workbench-maintenance:0.5.4-local`. Схема базы **0.5.0**, ревизия Alembic `0005_remove_oidc`. Номер приложения и теги образов двигаются вместе. Номер схемы — нет.

## Порядок чтения

1. [rules.md](rules.md) — что нельзя ломать и как вносить правку.
2. [architecture.md](architecture.md) — процессы, границы, откуда берётся конфигурация.
3. [domain.md](domain.md) — пользователи, кластеры, учётные данные, запуски, находки.
4. [capabilities.md](capabilities.md) — что уже доступно и чем каждый режим отличается.
5. [worker.md](worker.md) — очередь, сбор и действия, которые могут изменить кластер.
6. [api.md](api.md) — HTTP-маршруты и коды ошибок.
7. [ui.md](ui.md) — экраны, роли и клиентские правила.
8. [tests.md](tests.md) — чем покрыто поведение и как запускать проверки.
9. [operations.md](operations.md) — Compose, секреты, версия, перезапуск проверочного стека.

## Что считать устаревшим

Каталоги `docs/*.md` вне `docs/agent/` и корневой [README.md](../../README.md) — история контрактов и проверок. Они нужны для миграции 0.1–0.4 и для того, чтобы не переписать замороженные схемы. Часть ограничений в корневом README уже не совпадает с кодом: живые сканеры, расписания, расширенная проверка, оператор, импорт Falco/Tetragon и точечное исправление в коде есть. Единый вход в приложение по-прежнему не сделан. При расхождении верьте `docs/agent/` и исходникам, которые он называет.

Не присылайте в чат, issue или логи kubeconfig, токены, закрытые ключи и содержимое `.local`.
