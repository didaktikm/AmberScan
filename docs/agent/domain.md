# Предметная модель

Таблицы описаны в `src/workbench/db.py`. Сторож `require_runtime_schema` пускает запросы только при единственной строке `workbench_schema.version = 0.5.0` и `alembic_version = 0005_remove_oidc`.

## Пользователи и сессия

Роли: `administrator`, `auditor`, `security_lead`, `viewer`.

- `SCAN_ROLES` — администратор, аудитор, руководитель ИБ: запуск, импорт, личный отзыв, расписание.
- `REVIEW_ROLES` — администратор и руководитель ИБ: принять риск и ложное срабатывание. Аудитор может только подтвердить находку. Наблюдатель не меняет разбор.
- Администратор видит все готовые кластеры без grant. Остальные — только строки `cluster_grants`.

Вход: `POST /api/login`. Пароль проверяется в постоянном времени, неверная пара не раскрывает, существует ли пользователь. Пять ошибок подряд запирают учётную запись на пять минут. С одного адреса не больше 30 попыток за пять минут. Успешный вход удаляет прежние сессии этого пользователя.

Cookie `workbench_session`, HttpOnly, `SameSite=Lax`, восемь часов. Мутации требуют заголовок `x-csrf-token` из ответа входа. Origin и Host сверяются с `public_origin`.

Повторное подтверждение администратора: `POST /api/admin/reauth` с паролем. Окно около пяти минут. Его требуют отзыв всех авторизаций кластера, смена области namespace, удаление подключения и запись политики egress.

## Кластер

`auth_type` только `kubeconfig`. Поля, которые видит клиент, собирает `cluster_view`: id, name, environment, context, server, namespaces, lifecycle, `access_revision` (это `auth_generation`), статус `authorized` или `authorization_required`, срок личных данных.

Жизненный цикл:

1. Черновик (`lifecycle=draft`) живёт не дольше 24 часов, принадлежит создателю, другим администраторам не показывается. У пользователя не больше 10 живых черновиков.
2. `POST /api/cluster-drafts` принимает kubeconfig, контекст, имя, окружение и режим хранения. Исходный YAML не пишется. Сохраняется нормализованный token или клиентский сертификат.
3. Повтор того же API, контекста и CA без другого имени — `cluster_duplicate`. То же подключение под новым именем возможно только с `accept_alias: true`.
4. Обнаружение namespace и preflight не расширяют сохранённый список. Финализация черновика переводит его в `ready`, увеличивает поколение и оставляет только выбранные имена. Успех — все выбранные GET завершились, либо оператор явно принял частичное покрытие из одних 403.
5. Готовое подключение можно переименовать (`PATCH /api/clusters/{id}`, имя и окружение). Адрес, CA и контекст не меняются.
6. Удаление (`DELETE`, нужен недавний reauth) стирает локальные запуски, находки и само подключение. Объекты Kubernetes не удаляются.

Смена сохранённого списка namespace (`PATCH .../scope`) тоже требует reauth и свежего preflight. Если набор имён изменился, поколение растёт, все личные учётные данные этого кластера гасятся, активные запуски отменяются.

## Учётные данные Kubernetes

Режимы в `rollout.storage_deadline`:

| Режим | Потолок | Особенность |
| --- | --- | --- |
| `run_only` | 1 час и не дольше сессии | Строка привязана к сессии. Расходуется при постановке запуска, не при discovery |
| `persistent` | 24 часа | Можно переиспользовать, пока срок не вышел |
| `days_30` | 30 суток | Нужен для расписания |

Если в kubeconfig виден срок токена, берётся более ранний конец. Истёкшее нельзя поставить в очередь.

Grant даёт другому пользователю видеть кластер. Он не копирует kubeconfig. Каждый запускающий импортирует свой файл в то же подключение: сервер, CA и контекст должны совпасть.

Отзыв личной авторизации не отзывает токен в Kubernetes. Отзыв «для всех» гасит локальные копии и просит отмену активных запусков.

## Запуск и находка

`Run.source` говорит worker, что выполнять:

| source | Кто ставит | Что делает worker |
| --- | --- | --- |
| `api` и снимки расписания | обычный `POST /api/runs` или планировщик | встроенный инвентарь, только GET |
| `scanners` | действие `live_scanner` | закреплённые Trivy и Kubescape |
| `extended` | действие `extended` | временный непривилегированный под, затем удаление |
| `operator` | действие `operator` | фиксированные объекты только на чтение |
| `remediate` | действие `remediate` плюс аудит `remediate_target` | патч одного контроллера |
| `import:*` | импорт отчёта | разбор JSON без похода в кластер |

Область запуска — ровно ключи `namespaces`, `max_objects`, `timeout_seconds`, `inventory_version`. Версия инвентаря сейчас `1` (`namespaces.INVENTORY_VERSION`). Лишние ключи запрещены. Идентификатор находки для исправления не кладётся в scope: он пишется отдельной строкой аудита, потому что колонка `source` короткая.

Активные состояния: `queued`, `running`. Пока у кластера есть такой запуск, второй не ставится. Общий потолок очереди — `max_queued_runs` (20).

Находка дедуплицируется по `fingerprint`. Повторный импорт обновляет `last_seen` и не плодит строки. Разбор (`disposition`): `open`, `confirmed`, `accepted_risk`, `false_positive`.

Журнал `audit_events` не каскадно удаляется вместе с кластером. Расписание — не отдельная таблица, а последняя запись аудита `read_only_schedule` на id кластера.
