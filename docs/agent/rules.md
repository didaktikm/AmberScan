# Правила правки

## Версия

Каждая правка репозитория поднимает патч приложения: сейчас `0.5.4`, следующая правка — `0.5.5`. Меняйте все эти места одним коммитом:

- `src/workbench/__init__.py` — `__version__`
- `pyproject.toml` и строка пакета в `uv.lock`
- `frontend/package.json`
- `compose.yaml` и `compose.maintenance.yaml`: тег образа и `APP_VERSION`
- `Dockerfile`: оба `ARG APP_VERSION=`
- `README.md`, `docs/KUBECONFIG-AUTH.md`, значения по умолчанию в `tests/smoke_compose.py` и `tests/smoke_namespace_postgres.py`
- ожидание версии в `tests/test_api.py`

`tests/test_release_version.py` проверяет, что теги образов и аргумент сборки равны `__version__`. Схему `migrations.SCHEMA_VERSION` и ревизию `0005_remove_oidc` не повышайте без отдельной миграции. Исторические дайджесты в `docs/KUBECONFIG-ONLY-VERIFICATION.md` не переписывайте: это протокол уже собранного образа 0.5.0.

## Безопасность, которую нельзя ослабить

- Обычный аудит ходит в Kubernetes только GET. Запись возможна лишь у запуска с `source` из `extended`, `operator`, `remediate`, и только по URL, которые пропускают `validate_action_url` и `assert_safe_write`.
- Не скачивайте бинарники сканеров и не включайте сборщик узлов Trivy. Пути задаются `WORKBENCH_TRIVY_BIN` и `WORKBENCH_KUBESCAPE_BIN`: абсолютные, без `..`, без поиска в `PATH`.
- Образ оператора — `WORKBENCH_OPERATOR_IMAGE`, с явным тегом, не `:latest`. Без него постановка оператора в очередь отвечает `configuration_required` и ничего не создаёт.
- Не добавляйте произвольные манифесты. Исправление — одна встроенная находка на Deployment, StatefulSet или DaemonSet, патч strategic merge, UID объекта должен совпасть.
- Единый вход (`team_sso`) не делать до отдельного решения. Локальные учётные записи остаются.
- Не храните исходный kubeconfig. В базе лежит нормализованный token или клиентский сертификат, зашифрованный `Vault`.
- Не публикуйте PostgreSQL и не открывайте API наружу. Штатный порт — `127.0.0.1:8080`.
- Не запускайте `docker compose down -v` и не удаляйте `.local/master-key`. Повторный `init-db` на уже живой базе с данными не нужен: при схеме 0.5.0 он выходит сразу, но на старой схеме он откажется, а не обновит её.

## Как вносить изменение

Ветка от `dev`, не от `main`. После правки откройте pull request в `dev` и влейте его, не дожидаясь ручного слияния. Затем пересоберите образы с новым тегом и перезапустите проект Compose `amberscan-smoke` так, чтобы API снова слушал `127.0.0.1:8080`. Том базы и `.local` сохраняйте. Проверка: `GET /api/health/ready` возвращает `{"status":"ready"}`, а `GET /api/health/live` показывает новый номер.

Интерфейс на русском. После изменения экрана проверьте поведение в браузере, не только снимок вёрстки.

Публичные тексты ошибок — `DomainError`. Код ошибки стабилен, текст можно показать оператору. Не возвращайте тело запроса, токены и фрагменты kubeconfig в ответе.
