# Очередь и действия

Worker — отдельный процесс `src/workbench/worker.py`. Идентификатор `worker-<uid>`. Пульс пишется в таблицу `workers`. UI считает обработчик offline, если пульс старше 60 секунд.

## Порядок одного такта

Транзакции раздельные, чтобы чистка каскадов не ждала блокировку запуска:

1. `cleanup_expired_drafts` — просроченные черновики.
2. `cleanup_expired_authorizations` — просроченные сессии и личные учётные данные.
3. `purge_expired_results` — локальные завершённые запуски и их находки старше `max(retention_days, 90)` суток. Аудит, учётные данные и кластер остаются. Короче 90 дней настроить нельзя.
4. `enqueue_due_schedules` — для включённого расписания ставит GET-инвентарь. Режим `days_30` при этом не расходуется. Период `periodic` — 24 часа, `watch` — 6 часов. Уже активный запуск кластера пропускается.
5. `recover` — `running` с истёкшей арендой становится `interrupted`, снимок учётных данных стирается, повтор сам не стартует.
6. `claim` — один самый старый `queued` переводится в `running`, аренда `lease_seconds`.

Дальше `execute`. Снимок расшифровывается в родителе и передаётся в дочерний процесс `spawn`. Родитель снимок забывает. Дочерний `collect` строит `RunHTTP` и вызывает `actions.perform`. Пока дочерний жив, родитель продлевает аренду и проверяет отмену, срок и область. Потолок времени — `timeout_seconds` области. Успех публикуется только если снимок и область всё ещё те же. Иначе запуск не считается успешным.

Коды остановки и русские тексты — `Runner.finish_error`. Процесс, который не завершился, получает terminate, затем kill.

## Что разрешено HTTP запуска

`RunHTTP.get_json` пускает только URL инвентаря внутри сервера снимка и выбранных namespace (`validate_inventory_url`).

`post_json`, `delete_json` и `patch_json` существуют лишь для source из `WRITE_SOURCES` (`extended`, `operator`, `remediate`). Перед обменом вызываются `validate_action_url` и `assert_safe_write`. Чужие заголовки авторизации не пробрасываются. Тело ответа не удерживает блокировку базы на время сети.

Обычный `perform` без специального source вызывает `scan_inventory`: встроенные проверки и покрытие `cli:*` со статусом `not_checked`, потому что внешний сканер в этот запуск не входит.

## Запись в кластер

`extended`: создаёт под и затем удаляет его. В сохранённый результат адрес пода не кладётся.

`operator`: манифесты из `operator_manifests`. Исходный текст цикла в `operator.py` не содержит POST, PATCH, DELETE и PUT; это закреплено тестом. Установка без образа не доходит до worker.

`remediate`: `remediation_patch` строит один strategic merge. Перед патчем читается объект, UID сравнивается с находкой. Несовпадение — `conflict`, патч не отправляется.

`queue_confirmed_action` только создаёт строку `Run` и аудит. Сама функция в API-запросе в кластер не ходит.
