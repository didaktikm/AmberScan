# Проверка вёрстки и русской локализации

Дата: 16 ноября 2026. Область: frontend AmberData Kubernetes Workbench 0.5.0.

## Исправлено

- У строк выбора пространств имён явно задано горизонтальное направление: общий стиль `label { flex-direction: column }` больше не ставит флажок над названием. Убраны стандартные внешние отступы checkbox, из-за которых длинные имена переносились под флажок на ширине 360 px.
- Весь блок выбора ограничен по высоте: внутренняя область `min(34rem, 65dvh)`, поиск и счётчик сверху, одна прокручиваемая область для списка, предупреждений, действий и ручного ввода. Новые страницы и раскрытие ручного ввода не увеличивают блок сверх границы. Отдельной вложенной прокрутки списка нет.
- Открытый native dialog использует flex-column, заголовок не прокручивается вместе с содержимым, содержимое ограничено viewport и прокручивается внутри. Очень длинный заголовок отдельно ограничен `min(12rem, 30dvh)` и прокручивается, не скрывая кнопку закрытия и основное содержимое. Закрытый dialog остаётся скрытым штатным механизмом браузера. Добавлен перенос длинных кнопок в формах и футере, исправлены минимальные размеры grid-колонок.
- Ошибка ручного ввода или массового выбора автоматически показывается прокруткой только внутренней области селектора, в том числе при повторении одинаковой ошибки; положение страницы и модального окна не меняется.
- Приведены к единой русской терминологии подписи, подсказки, состояния и доступные имена элементов подключения, выбора области, проверки доступа, повторного импорта, настроек, результатов и импорта отчётов.
- Добавлены русские сообщения для однозначных кодов сетевых ошибок, ошибок получения списка и известных типов ошибок валидации. Машинные коды сохранены. Для общих кодов вроде `invalid_input`, `conflict`, `forbidden` и неизвестных ошибок сохраняется исходная диагностика: причины не подменяются универсальным переводом.
- Значения API, реальные имена объектов, технические идентификаторы и произвольные тексты импортированных отчётов/evidence не переводились.

Логика выбора не изменена: первоначально пустой выбор; фильтр, обновление и продолжение загрузки не выбирают новые элементы автоматически; максимум 100 выбранных пространств имён; ручной ввод и состояния 403/неполного/устаревшего списка сохранены.

### Реальный Chromium: геометрия и взаимодействия компонентов


Требования: существующие frontend/node_modules и установленный Chrome. По умолчанию macOS-путь `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`; для другой установки задать `CHROME_BIN`.

Точный viewport задаётся iframe, поскольку минимальная ширина настольного окна Chrome не соответствует мобильной ширине. Приложение, пароли, cookies, kubeconfig и Kubernetes не используются.

## Ограничения

- Это геометрические и программные interaction-проверки реальных компонентов, **не полный E2E работающего приложения**. Все три сценария использования селектора покрыты существующими компонентными тестами; реальный браузер проверяет общий селектор и диалог на синтетических данных.
- Native touch, полный клавиатурный маршрут, screen reader и ручной визуальный просмотр всех экранов не проверены этим прогоном.
- Браузер Cherry смог прочитать экран входа `http://127.0.0.1:8080`, но screenshot вернул `not_found`. Авторизация не обходилась.
- Технические имена и исходные данные сканеров сохранены; отдельные неизвестные/общие backend-сообщения могут оставаться на английском. Полная локализация произвольных внешних отчётов не заявляется.
- Backend, схема/данные БД, конфигурация доступа и Kubernetes не изменены. Backend-тесты не запускались: изменения только frontend.
- **Работающий Docker Compose не обновлялся.** Собраны локальные frontend-артефакты; для появления исправлений в контейнерном интерфейсе необходимо отдельное согласованное развёртывание. Перезапуск контейнера без пересборки образа эти исходники не подхватит.
